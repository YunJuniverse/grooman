# 31. 세션 마감 및 머지 착지

> 작업 단위를 끝내고 main 에 착지시키기까지의 절차 정본. CLAUDE.md §2 는 이 문서를 가리키는 포인터만 둔다(methodology:ADR-007 D3).
> 여기 적힌 것의 대부분은 **도구가 fail-closed 로 막는다** — 외울 규칙이 아니라, 막혔을 때 왜 막혔는지 찾아보는 곳이다.

---

## 1. 마감 — 4개 라이브 파일

작업 단위가 끝나면 넷을 갱신한다. `wrap` 이 sha256 으로 **실제 내용 변경**만 인정한다(mtime 만 바꾸면 통과 못 함).

| 파일 | 담는 것 | 담지 않는 것 |
|---|---|---|
| `TODO.md` | 완료 → Done · 신규 항목 | 완료 상세(git·PR·스냅샷으로) |
| `HANDOFF.md` | 상태 보드 — Working on · 오픈 이슈 · Recent 5건(한 줄씩) | 세션 서사 |
| `.ai/checkpoint.md` | 세션 서사 바통 — 이번 세션 절을 맨 위에: 방금 한 것 · 다음 구체 행동 · 막힌 것 | 누적 상태(HANDOFF 로) |
| 관찰 로그 | `observe` CLI 로 작성(지침 03 §5) | 손으로 쓴 파일(형식 오류로 wrap 실패) |

- 같은 세션의 연속 PR·land 재시도는 그날 관찰 로그를 같은 slug 로 `--force` 갱신하면 4/4 로 인정된다(methodology:ADR-006 D3).
- 마찰(`--friction`)·프롬프팅(`--rounds-total`·`--prompting`) 기록 규칙은 지침 03 §5.2·§5.3.

### 크기 상한

| 파일 | 권장 | wrap --strict 실패 |
|---|---|---|
| HANDOFF.md | 150줄 | 규정 2배 |
| .ai/checkpoint.md | 200줄 · 최근 3절 | 규정 2배 |
| TODO.md Done | 6건 | — (경고) |

초과하면 `methodology.py rotate --apply`(checkpoint 는 `rotate --checkpoint --apply`)로 회전한다. 삭제가 아니라 `40_dev/snapshots/live-archive/` 이관이다. 비대한 HANDOFF 는 부팅 프라이머로 쓸모가 없다.

## 2. ship — 커밋·push 는 이것 하나

```
methodology.py ship -m "<conventional 메시지>"
```

wrap --strict → manifest 검사 → sensitive 파일 검사 → (test/build) → commit → push 를 한 번에 한다. `git add`·`commit`·`push` 를 따로 치지 않는다. ship 이 막는 것:

- 4개 라이브 파일 미갱신
- sensitive 의심 파일(`--allow-sensitive` 로만 통과)
- 새 1MB 이상 파일(`--allow-large`)
- **스택-PR** — 열린 PR 브랜치 위에 쌓은 브랜치(§4)
- **공유 체크아웃의 미추적 신규 파일** — 전부 이 세션 것일 때만 `--allow-shared`(지침 30 §1)
- **dev 서버 실행 중 build** — 수동 빌드는 `60_tools/build-guard.sh` 경유

로컬 push 가드는 `methodology.py hooks install`(pre-push: manifest + wrap --strict).

## 3. land — 머지 착지

```
methodology.py land        # 또는 ship --land
```

PR 머지 → 기본 브랜치 동기화 → `maincheck` 까지 한다.

- **자동 머지는 Class A + CI green 일 때만.** 변경 경로나 TODO 항목에 Class B/C 트리거(마이그레이션·인증·과금·외부 API 계약·백그라운드 작업·CI 파이프라인·법무/정책)가 걸리거나, CI 가 실패·진행 중이거나, 판정 자체가 불가하면 land 가 거부하고 사람을 부른다(methodology:ADR-004).
- `.methodology-version` 의 `required_checks` 에 적힌 체크는 전부 SUCCESS 여야 한다(methodology:ADR-006 D5).
- `--no-ci-check` 는 무검증 머지라 기본 금지. CI 가 결제·인프라로 안 돌 때는 TODO Blocked 의 PM 판정 + `--local-ci`.
- 사람이 이미 머지한 PR 에 land 를 다시 돌리면 도달 확인만 한다.
- **머지 기록 커밋·PR 을 만들지 않는다**(methodology:ADR-007 D1). land 는 커밋을 만들지 않는다.

## 4. 스택-PR 금지 · Done 은 PR 안에

- PR 은 **main 직행 단일 PR** 만. 앞 PR 이 머지된 뒤 main 에서 새로 분기한다. 중간 브랜치로 머지되면 «머지됨»이어도 main 에는 코드가 없다(6개 repo 실사고, METH-120).
- **TODO Done 전이와 HANDOFF 한 줄은 그 작업 PR 안에 싣는다.** main 에 못 간 PR 은 Done 도 main 에 없다.
- **main 의 `TODO.md` 만 사실이다.** 열린 브랜치의 Done 은 예정이다.
- 배포 판정 전에는 `methodology.py maincheck <sha>` 로 main 도달을 기계 확인한다.
- main 에 직접 push 하지 않는다 — 예외 없음.

## 5. 외부 게이트 = Blocked

대표 승인·결제·자격증명·타인 응답처럼 **사람이나 외부만 풀 수 있는** 대기 항목은 TODO `## Blocked` 로 옮기고 HANDOFF Blockers 와 일치시킨다. Ready 체크박스나 notes 산문에 숨기지 않는다(METH-122 — 4개 repo 에서 Blocked 0건인데 실제 병목 다수, 최장 19일 은닉).

- 등록 전에 기존 `## Blocked`·HANDOFF Blockers 를 grep 해 같은 건(PM 판정 포함)이 있는지 본다(METH-147).
- 월 1회 후속 결정과 대조해 stale 을 종결한다.
- 새 TODO ID 는 `methodology.py reserve` 로 예약한다(지침 30 §7).

## 6. 외주 인계

코드만 추출: `methodology.py export --path <p> --dry-run`. 방법론 파일과 sensitive 파일은 기본 차단(`--allow-sensitive`), 압축은 `--zip`.
