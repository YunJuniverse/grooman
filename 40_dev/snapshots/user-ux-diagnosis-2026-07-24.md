# 사용자 관점 UX 진단 (2026-07-24)

> 기계 지표(Lighthouse)가 아니라 **실제로 그루밍 정보를 찾으러 온 사람의 흐름**을 따라가며 관찰.
> 저니: 첫 방문(홈) → 카테고리 둘러보기 → 검색 → 글쓰기 진입.
> 방식: 로컬 prod 빌드(실 Supabase 연결)를 375×812 모바일로 관찰 + 대비 정량 측정(브라우저 스크립트).
> talmo-com의 동일 진단 형식을 따름(권고 7). **이 문서는 진단이며, 수정은 우선순위대로 별도 처리.**

## 결론

첫 화면의 구조·규제 처리·접근성 기반은 탄탄하다. 그런데 **다크 모드(기본 테마)에서 거의 모든 페이지 제목이 보이지 않는다** — 첫인상에서 바로 드러나는 신뢰 훼손이다. 그리고 **콜드스타트(글 0건) 상태의 화면이 "죽은 사이트"처럼 보인다** — 봇 시딩 전 공개하면 첫 방문자가 빈 화면만 본다.

---

## 심각 — 첫인상에서 바로 드러나는 지점

### 1. 다크 모드에서 페이지 제목이 안 보인다 (대비 1.05:1)

기본 테마가 다크인데, 카테고리 제목·검색 제목·글 제목 등 **13개 화면의 `<h1>`이 `text-gray-900`(#111827) 하드코딩**이라 다크 배경(#10131a) 위에서 대비가 **1.05:1**이다(WCAG AA 4.5:1의 1/4). 사실상 안 보인다.

- 정량: `/hair` 제목 "헤어케어·탈모" 1.04:1, `/search` 제목 "검색" 1.05:1 (브라우저 실측).
- 대상 13곳(`dark:` variant 없음): 카테고리·검색·태그·글 상세·프로필·마이페이지·글쓰기·관리자·로그인 제목 + 관련글/댓글 섹션 제목.
- **주의**: `privacy`·`terms`는 컨테이너가 `bg-white` 하드코딩이라 다크에서도 흰 배경 → 이 두 곳은 `dark:` 넣으면 **역으로 흰 글자가 됨**. 일괄 치환하면 안 되고 배경 맥락을 봐야 한다.
- **처리**: 이 진단 중 일괄 수정을 시도했다가 위 white-on-white 위험을 확인하고 되돌렸다. **전역 다크모드 감사(PERF-2 백그라운드 작업)로 이관** — 그쪽이 배경 맥락까지 본다.

### 2. 콜드스타트 화면이 "죽은 사이트"로 보인다

글 0건 상태에서 홈은 인기 게시글 "아직 인기 게시글이 없습니다" + 최신 글 "아직 게시글이 없습니다"만 뜬다. 카테고리 6개 타일은 색이 있어 살아 보이지만, **스크롤 아래 절반이 빈 안내문 두 개**다.

- 이건 버그가 아니라 **공개 시점 결정 문제**다. ADR-0002(봇 시딩)·SOP_public-release-gate가 이미 "봇으로 초기 콘텐츠를 채우고 공개 직전 제거"를 정해뒀으므로, **봇 시딩 전에 외부에 노출하지 말 것**이 실질 대응이다.
- 개선 여지: 빈 상태 문구가 "첫 번째 글을 작성해보세요!"인데, 비로그인 사용자에겐 **로그인 유도 + 무엇을 쓸 수 있는지 예시**가 더 낫다(90-9-1 원칙상 첫 방문자는 눈팅족).

## 보통 — 흐름이 끊기는 지점

### 3. 검색 페이지에 검색창이 없다

`/search`에 직접 오면 "검색어를 입력해주세요"만 있고 **입력창이 화면에 없다**. 상단 헤더의 돋보기 아이콘을 눌러야 검색 UI가 열리는 구조로 보인다. 검색 페이지에 왔는데 그 자리에서 검색을 시작할 수 없는 건 흐름 단절이다.

- 개선: `/search` 본문 상단에 검색 입력창을 두어, 이 페이지에서 바로 타이핑 가능하게.

### 4. 첫 화면에 "그루맨이 뭐 하는 곳인지"가 없다

홈 최상단이 바로 카테고리 타일이다. 비로그인 첫 방문자에게 **한 줄 소개(예: "남성 그루밍 정보를 나누는 커뮤니티")**가 히어로로 없다. 메타 description엔 있으나 화면엔 없다.

- talmo 진단도 같은 항목을 지적했다(§6 "첫 화면에 뭐 하는 곳인지 없다"). 커뮤니티는 검색 유입이 많아 **랜딩 맥락 제공**이 이탈을 줄인다.

## 사소

- **5.** HOT 탭이 "실시간 / 일간 HOT / 주간 HOT" 3개인데 글 0건이라 전부 비어 동일하게 보인다(콜드스타트 부산물, §2와 동일 원인).
- **6.** 하단 네비 "HOT" 아이콘만 주황, 나머지는 회색 — 활성 페이지가 아닌데 HOT이 상시 주황이라 "지금 HOT 탭인가?" 혼동 여지(경미).

## 잘 되어 있는 것 (냉정하게 균형)

- **카테고리 색 시스템**이 명확하다 — 6개 카테고리가 각기 다른 색 타일·배지로 구분돼 한눈에 들어온다.
- **규제 처리가 화면에 배어 있다** — [자동수집] 배지, 표시광고 경고(글쓰기), 약관의 임시조치 절차. 경쟁 커뮤니티 대비 강점.
- **폰트·한글 조판**이 좋다 — Pretendard dynamic-subset(256KB)·`word-break: keep-all`로 한글이 자연스럽게 끊긴다.
- **하단 고정 네비**가 모바일 이동을 매끄럽게 한다. 탭 타깃도 충분히 크다.
- **접근성 기반** — 아이콘 aria-label, 시맨틱 헤딩, 로그인 버튼 대비(indigo-600 6.29:1, 이번 세션에 이미 고침).

## 이 진단이 Lighthouse와 다른 점

Lighthouse(2026-07-24 실측)는 홈·`/hair`·`/search`에서 Accessibility 95~100을 줬다. 그런데 **13개 제목이 안 보이는 문제를 Lighthouse는 못 잡았다** — 측정 시점에 그 페이지들의 제목이 뷰포트에 없었거나(콜드스타트), axe 규칙이 특정 조합을 놓쳤기 때문이다. **사람이 저니를 따라가야 잡히는 문제**가 실재함을 보여준다.
