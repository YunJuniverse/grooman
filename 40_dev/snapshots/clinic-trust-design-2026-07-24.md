# clinic 신뢰 장치 설계 (2026-07-24)

> 날짜 산출물(라이브 아님). talmo-com 교차조사 권고 8번의 **설계 스냅샷** — 스키마·기획 변경(Class B)이 필요해 코드로 바로 들어가지 않고, 빌드 착수 전 결정용 근거를 정리한다.
> 근거: `40_dev/snapshots/talmo-com-cross-project-research-2026-07-24.md` §3.3~3.4.

## 왜 clinic만 별도 신뢰 설계가 필요한가

clinic(시술·성형 후기)은 grooman에서 **가장 민감·고관여** 카테고리다. 사용자는 큰돈·몸에 관한 결정을 앞두고 후기를 읽으러 온다. 동시에 **의료법 규제가 가장 빡빡**하다(§56 광고 주체 한정·§27 유인). 이미 이번 세션에서 재게시 차단(LEGAL-2)을 넣었지만, 그건 *방어*다. clinic이 실제로 신뢰받으려면 *능동적 신뢰 장치*가 필요하다.

## 참고 패턴 — 강남언니 3종 (3표 검증, talmo 리서치 §1-④)

| 장치 | 강남언니 원형 | grooman 적용 가능성 |
|---|---|---|
| ① 방문 인증 | 영수증·결제문자·이체내역 → 내부 검증 → 인증 태그 | **부분 가능** — grooman은 결제를 안 하므로 "영수증"은 없다. 다만 시술 인증 이미지 업로드 → 운영자 수동 확인 → `verified` 배지는 가능 |
| ② '아쉬운 점' 필터 | 단점 구조화 입력 + 단점만 보기 필터 | **가능·권장** — 스키마에 `downside` 텍스트 필드 추가, 목록에서 "아쉬운 점 있는 후기만" 필터 |
| ③ 완결 동선 | 후기 열람 → 앱 내 예약·결제 → 재예약 | **불가·의도적 배제** — 예약·유인 동선은 의료법 §27 정면 위반. grooman은 여기를 **의도적으로 비워둔다**(= 중립성) |

## talmo 시드 교훈 — 봇 데이터가 빠지는 함정

talmo TALMO-050 실측: 후기 평점이 **3~5점만** 분포해서 **'아쉬운 점' 필터가 공허**했다(단점을 쓴 후기가 거의 없어 필터가 빈 결과). → 1~5점 분포로 재생성.

**grooman 함의**: clinic에 '아쉬운 점' 필터를 넣으려면, **봇 시딩 데이터부터 부정적 경험을 포함**해야 한다. 안 그러면 필터 UI만 있고 내용이 없다. ADR-0002 봇 시딩 시 clinic은 평점·만족도 분포를 의도적으로 넓게 잡을 것.

## 설계 제안 (빌드 시 결정 대상)

### A. 최소안 (스키마 1필드 + UI)
- `posts`에 clinic 전용 메타를 넣기보다, **구조화 입력을 본문 템플릿으로** 유도: clinic 글쓰기 시 "좋았던 점 / 아쉬운 점" 2개 섹션 프리셋.
- 장점: 스키마 무변경(Class A). 단점: 필터·집계 불가(자유 텍스트).

### B. 권장안 (경량 스키마)
- `post_clinic_meta` 테이블: `post_id`, `has_downside`(bool), `verified`(bool), `verified_by`/`at`.
- clinic 글쓰기에 "아쉬운 점" 필수 입력(빈 후기 방지) + 시술 인증 이미지 선택 업로드.
- 목록에 "인증 후기만" · "아쉬운 점 있는 후기만" 필터.
- 운영자 큐(GRM-012 신고 큐 확장)에서 인증 이미지 확인 → `verified` 토글.
- Class B(스키마·RLS 추가). 재게시 차단(LEGAL-2)과 정합.

### C. 익명 옵션 (talmo policy.ts 패턴)
- clinic을 **선택적 익명 보드**로: 글 단위 익명 토글. talmo는 시술 보드를 `anonymousOnly`로 강제했으나, grooman은 "자발적 후기는 위반 아님"(검토메모 §2) 근거로 **강제까지는 안 가고 옵션**으로.
- ⚠️ talmo가 잡은 정책 구멍: 익명 보드에서 **글만 익명 강제되고 댓글은 아니던 버그**. grooman이 익명을 넣으면 `createComment`에도 같은 정책 적용할 것.

## 권고

- **B안(경량 스키마) + C안(익명 옵션)**을 P2~P3에 배치. clinic이 실제로 활성화되기 전(현재 글 0건)에는 급하지 않다.
- **선결 조건**: 봇 시딩(ADR-0002) 시 clinic 후기의 만족도 분포를 넓게 — '아쉬운 점' 필터가 공허해지지 않도록(talmo 교훈).
- **하지 말 것**: 예약·상담·가격 노출 동선(§27 위반). clinic은 "정보를 나누는 곳"이지 "병원으로 보내는 곳"이 아니라는 경계를 코드·카피 양쪽에서 지킬 것.

## 이번 세션에서 하지 않은 이유

스키마 변경(Class B)은 마이그레이션·RLS·기획서 정합이 따라야 하고, clinic이 아직 글 0건이라 **지금 만들면 검증할 데이터가 없다.** 방법론상 "빌드 전 결정 게이트"에 해당하므로 설계만 남기고 사용자 결정을 기다린다. GRM-016 체크박스로 등록됨.
